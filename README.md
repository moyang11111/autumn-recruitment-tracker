# 秋招资源汇总平台

这是一个自用的静态秋招信息聚合与投递进度管理工具，面向应届生和求职者。它集中展示央国企、私企和外企招聘信息，支持公开招聘源自动更新、按城市发现职位，并允许用户在本机记录每条招聘信息的投递状态。

## 快速开始

项目不依赖构建工具和第三方包，直接双击根目录的 `index.html` 即可打开。若浏览器对本地文件的脚本或下载行为有限制，可以在项目根目录启动一个可选的本地静态服务器：

```bash
python -m http.server 5173
```

然后访问 <http://localhost:5173/>。也可以使用任意其他静态文件服务器，平台不需要后端服务。

页面会优先读取 `data/jobs.generated.js` 中的公开职位快照，并与 24 条内置示例数据合并。同步快照缺失、为空或格式无效时，页面会自动回退到示例数据。

## 自动更新招聘信息

- `data/sources.json` 保存公开招聘来源。目前接入 Greenhouse Job Board 和 Lever Postings 两类无需密钥的公开 GET 接口。
- `scripts/sync-jobs.mjs` 负责拉取、规范化城市、去重、校验 HTTPS 链接，并同时生成 `data/jobs.generated.json` 和可通过 `file://` 加载的 `data/jobs.generated.js`。
- 某个来源失败时只隔离该来源，并保留上一份有效快照；其他来源仍可继续更新。
- `.github/workflows/sync-jobs.yml` 支持手动执行，并每 6 小时自动运行一次。测试通过且岗位内容确有变化时，才提交新的快照。

本地手动同步：

```bash
npm run sync
```

当前预置 Airbnb Greenhouse 和 Palantir Lever 两个公开来源。它们包含企业公开职位，不保证全部属于中国大陆校招或秋招岗位；应通过来源标签和企业官网再次核验。增加来源、失败回退规则和字段契约详见 `data/README.md`。

若 GitHub 仓库启用了严格分支保护，需要允许该工作流写入内容，或把工作流改成自动创建数据更新 PR，否则定时任务可以抓取但无法提交快照。

## 城市职位与投递状态助手

- 选择省份和城市后，页面会实时展示该城市的匹配岗位数、来源数和最后同步时间；可以与关键词、企业性质、截止时间、投递状态组合筛选。
- “投递状态助手”允许选择职位并粘贴招聘邮件、短信或通知文本，在浏览器本地识别已投递、笔试、面试、Offer、淘汰等状态。
- 助手只给出建议、置信度和命中依据；必须点击确认才会更新状态。通知文本不会上传，也不会写入 localStorage。
- 自动同步刷新后，同一岗位的本地状态优先；已产生投递进度但后来从公开来源下架的岗位仍会保留，未投递的下架岗位会自动移除。

## 数据与本地持久化

- `data.js` 提供 `globalThis.INITIAL_RECRUITMENT_DATA`，包含 24 条可直接用于演示的初始化记录。
- `data.js` 中的日期、状态和招聘链接是演示数据；日期是模拟的 2026 年 8—10 月秋招时间，请务必以企业官方招聘页面为准。自动同步记录会显示独立的来源标签。
- 首次打开时，前端将当前有效数据写入 localStorage；用户后续修改状态时写回 `autumn-recruitment-tracker:v1`。同步刷新只覆盖招聘字段，不覆盖同 ID 的本地投递状态。
- “恢复示例数据”一类操作只应清除该 key 并重新复制初始化数组，不会影响浏览器其他站点的数据。
- 每次状态改变都要同步写入该记录的 `statusUpdatedAt`（ISO 8601 时间字符串），列表可以据此展示“更新于”时间，并支持截止时间、投递状态和最近更新时间的正序/倒序排序。
- 存储和展示的校招链接仅接受 `https:` 协议；日期字段必须为有效的 `YYYY-MM-DD`，且开放日期不得晚于截止日期。

## 导出 CSV 并在 Excel 中打开

页面中的“导出 CSV”会将当前数据导出为 UTF-8 CSV。使用 Excel 时，推荐选择“数据 → 自文本/CSV”，编码选择 `UTF-8`，分隔符选择“逗号”，再加载文件。这样中文企业名、岗位类别和状态不会乱码。

如果使用 Excel 直接双击 CSV，较新版本通常会自动识别 UTF-8；若出现乱码，请改用“数据 → 从文本/CSV”导入。数组字段（例如多个岗位类别）建议在同一单元格中用 `、` 连接。

## 数据结构

每条 `INITIAL_RECRUITMENT_DATA` 记录的字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 全局唯一的招聘记录 ID |
| `companyName` | string | 企业名称 |
| `companyType` | enum | `央国企`、`私企`、`外企`、`事业单位`、`其他` |
| `openDate` | `YYYY-MM-DD` | 秋招开放日期；演示日期 |
| `deadline` | `YYYY-MM-DD` | 秋招截止日期；演示日期 |
| `province` | string | 公司所在省份/直辖市 |
| `city` | string | 公司所在城市 |
| `categories` | string[] | 招聘岗位类别，可为空数组但示例均提供类别 |
| `campusUrl` | string | 校招官网或企业官方招聘链接 |
| `status` | enum | 当前简历投递状态 |
| `statusUpdatedAt` | ISO 8601 string | 最近一次状态变更时间 |
| `isDemo` | boolean | 是否为演示数据；初始化记录均为 `true` |

同时，数据文件还暴露了 `globalThis.RECRUITMENT_STATUS_OPTIONS`、`globalThis.RECRUITMENT_COMPANY_TYPES` 和 `globalThis.RECRUITMENT_DATA_META`，方便界面复用枚举和演示数据提示。

自动同步快照通过 `globalThis.RECRUITMENT_SYNC_PAYLOAD` 暴露，顶层包含 `schemaVersion`、`generatedAt`、`sources` 和 `records`。同步记录使用 `jobCategories`，前端会兼容转换为现有的 `categories`；并增加 `sourceId`、`sourceName`、`sourceType`、`sourceUpdatedAt` 和 `fetchedAt`。公开来源未提供开放或截止日期时，对应字段为空，页面显示“待公布”。

## 投递状态字段

`status` 只能使用以下值，界面建议为每个值使用独立颜色标签，并允许用户手动更新：

1. `未投递`
2. `已投递`
3. `筛选中`
4. `笔试 / 测评中`
5. `面试中`
6. `已发 offer`
7. `终止流程 / 已淘汰`
8. `已接受 / 已拒绝 offer`

## 校验

无需安装依赖，运行：

```bash
npm test
```

该命令会检查初始化数据、同步适配器、来源失败回退、城市规范化、危险 URL、状态推断、历史岗位保留及城市筛选语义。如果应用文件已经集成到同一目录，还会检查 `index.html` 及常见脚本/样式入口和关键页面挂钩；也可以用下面的严格集成检查明确要求应用文件存在：

```bash
npm run test:integration
```

集成检查只匹配语义性的文本、常见 ID/data 属性和常见资源文件名，不要求固定 HTML 排版，便于 UI 层调整结构。

## 后续扩展建议

- 增加用户登录、个人简历/收藏夹，以及多设备数据同步。
- 用后端数据库替换 localStorage，支持多用户、权限和操作日志。
- 增加更多经过授权的企业官方 API/RSS/适配器，并为央国企招聘官网增加人工审核队列和页面变更检测。
- 增加“校招 / 实习 / 社招”分类规则，避免公开职位源中的社会招聘岗位混入秋招视图。
- 在用户主动授权后接入 Gmail / Outlook，只读取招聘通知并在本地或可信后端生成状态建议；企业 ATS 的真实流程状态仍需雇主授权接口。
- 增加截止日期提醒、微信/邮件通知、日历订阅和批量状态更新。
- 增加岗位去重、链接可用性检查、数据审核和“官方来源”标记，降低过期或误导信息风险。
- 增加按企业性质、城市、岗位类别和时间的统计趋势，以及 CSV/JSON 双向导入导出。

> 提醒：示例数据只用于演示产品交互，不构成招聘承诺或求职建议；投递前请核验企业官方公告和招聘链接。
